# RecordAgent iOS 国际化与中英文切换技术规范

> 适用范围：`RecordAgent` 原生 iOS 工程（iOS 17.0+ / SwiftUI / XcodeGen）  
> 目标：建立标准化、低侵入、易扩展的多语言架构，支持应用内“跟随系统 / 简体中文 / English”无重启即时切换，并为后续业务功能提供统一的编码与布局规范。

---

## 一、架构设计与核心机制

### 1. 语言偏好模型与生命周期
应用语言管理集中在 `Domain/Localization` 与 `AppEnvironment`，采用持久化存储 + 环境注入模式：

- **语言选项定义 (`AppLanguage`)**：
  - `system`（默认）：跟随 iOS 系统语言环境（`Locale.autoupdatingCurrent`）。
  - `zhHans`：固定强制简体中文（`Locale(identifier: "zh-Hans")`）。
  - `en`：固定强制英文（`Locale(identifier: "en")`）。
- **持久化方案**：
  - 通过 `@AppStorage("app_selected_language")` 保存用户显式选择的原始值。
  - 当值为 `system` 时，不写入固定区域标识，允许系统语言切换时应用自动跟随。
- **即时响应机制**：
  - 在 `RootCoordinatorView`（根视图）统一注入 `.environment(\.locale, currentLocale)`。
  - 针对根容器附加 `.id(currentLanguage)`，确保在设置中切换语言时，整棵视图树完成无缝热重绘，无需重启应用。

```
┌────────────────────────────────────────────────────────┐
│                   AppEnvironment                       │
│    @AppStorage("app_selected_language") -> AppLanguage │
└──────────────────────────┬─────────────────────────────┘
                           │ 注入环境
                           ▼
┌────────────────────────────────────────────────────────┐
│                 RootCoordinatorView                    │
│    .environment(\.locale, currentLocale)               │
│    .id(currentLanguage)                                │
└──────────────────────────┬─────────────────────────────┘
                           │ 沿环境向下传递
            ┌──────────────┴──────────────┐
            ▼                             ▼
   SwiftUI Views (自动继承)        Formatters (显式绑定环境)
   Text("home.title")             date.formatted(...)
```

## 二、工程配置与资源组织（XcodeGen）

### 1. 工程单一事实来源 (`project.yml`)
在 `project.yml` 中声明工程的默认语言与已知区域，确保每次 `xcodegen generate` 后多语言索引稳定有效：

```yaml
options:
  bundleIdPrefix: com.butvan
  deploymentTarget:
    iOS: "17.0"
  xcodeVersion: "16.0"
  defaultLanguage: zh-Hans
  knownRegions:
    - en
    - zh-Hans
```

### 2. 统一使用 iOS 17 String Catalogs (`.xcstrings`)
- **文件位置**：`RecordAgent/Resources/Localizable.xcstrings`
- **选用理由**：
  - 替代旧版分散的 `.strings` 和 `.stringsdict`。
  - 单一 JSON 格式统一管理各语言翻译、复数形态（Pluralization）、替代变量与状态标记（New / Translated / Stale）。
  - Xcode 编译时静态检查与自动语法提取支持。

## 三、开发代码规范（确保后续功能正常）

所有新功能开发（日历、财务、资料、记录、任务等）必须严格遵守以下 5 项编码准则：

### 1. 自定义组件接口契约：优先使用 `LocalizedStringKey`
- **规则**：自定义 UI 控件（如按钮、输入框占位符、标签卡片）接收文案参数时，必须定义为 `LocalizedStringKey`，而非裸 `String`。
- **反例（禁止）**：
  ```swift
  // 错误：传入 String 会绕过 SwiftUI 自动本地化查找，变成死文本
  struct CustomCard: View {
      let title: String
      var body: some View { Text(title) }
  }
  ```
- **正例（必须）**：
  ```swift
  // 正确：接收 LocalizedStringKey，自动享受 SwiftUI 环境的 Locale
  struct CustomCard: View {
      let title: LocalizedStringKey
      var body: some View { Text(title) }
  }
  ```

### 2. 文本拼接规范：禁止手动加号拼接，必须使用参数化插值
- **规则**：不同语言的语序截然不同，严禁使用 `+` 拼接句子或动态参数。必须将整句作为参数化模板。
- **反例（禁止）**：
  ```swift
  // 错误：中文为“已记录 128 天”，英文手动拼接后变成 "Recorded " + "128" + " days"，无法适应复数和倒装
  Text("已记录 " + "\(days)" + " 天")
  ```
- **正例（必须）**：
  ```swift
  // 正确：SwiftUI 会自动提取为格式化占位 "已记录 %lld 天" / "%lld days recorded"
  Text("已记录 \(days) 天")
  ```

### 3. 非视图层文本规范：使用 `String(localized:)`
- **规则**：在 ViewModel、Service 或非 View 结构体中需要产生文本时，必须使用类型安全的 `String(localized: "...", comment: "...")`。
- **正例**：
  ```swift
  public enum AppTab: Int, CaseIterable {
      case home, discover, profile
      
      public var title: LocalizedStringKey {
          switch self {
          case .home: return "tab.home"
          case .discover: return "tab.discover"
          case .profile: return "tab.profile"
          }
      }
  }
  ```

- 应用内语言切换下，非 View 的首页样例文案、分钟数与图表标签统一使用 `Services/Localization/AppLocalization.string(_:locale:)`；它根据传入语言选择 `.lproj` 资源包再格式化。仅向 `String(localized:)` 传 `locale` 无法保证切换翻译资源，相关回归见 `HomeTests.testSampleTextUsesRequestedLocale`。

### 4. 日期、时间与数字格式化：绑定当前环境
- **规则**：禁止写死包含中文年月日的格式模板（如 `yyyy年MM月dd日` 或 `HH:mm`）。必须使用 SwiftUI 原生环境感知的 Formatter 或显式设置 Locale。
- **正例**：
  ```swift
  // 推荐：使用 iOS 15+ 原生日期格式化 API，自动匹配当前 Locale
  Text(Date.now, format: .dateTime.month(.wide).day().weekday(.wide))
  // 中文自动输出：9月25日 星期五
  // 英文自动输出：Friday, September 25
  ```

### 5. 错误提示与状态响应：领域枚举映射
- **规则**：Service 层返回类型化错误枚举，禁止将服务端未本地化的纯中文字符串作为唯一展示文案。
- **正例**：
  ```swift
  public enum AuthError: LocalizedError {
      case invalidCredentials
      case networkTimeout
      
      public var errorDescription: String? {
          switch self {
          case .invalidCredentials:
              return String(localized: "auth.error.invalid_credentials", defaultValue: "账号或密码错误")
          case .networkTimeout:
              return String(localized: "auth.error.network_timeout", defaultValue: "网络连接超时，请重试")
          }
      }
  }
  ```

## 四、UI 布局自适应准则（防溢出与截断）

英文文本平均长度比中文长 30%~100%（例如“退出登录”4字符 vs “Log Out”7字符；“持续发光中” vs “Continuously shining”）。为确保双语布局完美适配，必须遵循：

1. **弹性尺寸**：文本容器严禁写死宽度（如禁止 `frame(width: 60)`）。优先使用 `frame(minWidth: ...)` 或自适应布局。
2. **文本缩放与折行**：
   - 导航栏标题、Tab 栏文字设置 `.minimumScaleFactor(0.8)` 与 `.lineLimit(1)`，防止文字溢出变省略号（`...`）。
   - 卡片说明文案与副标题允许适当折行（`.lineLimit(nil)` 或 `.fixedSize(horizontal: false, vertical: true)`）。
3. **按钮与标签间距**：按钮内边距预留横向弹性空间，避免英文单词紧贴按钮边缘。
