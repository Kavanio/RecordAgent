# RecordAgent iOS 开发前规划

> 状态：分阶段方案（2026-09-28 更新日历界面）。已确定 Swift、SwiftUI、Xcode、多用户服务器 API、桌面与 iOS 共用服务；当前先开发 iOS 界面和 API 请求层，首版目标是在个人 iPhone 上验证邮箱账户、主界面、设置与完整日历功能。

## 1. 产品边界

RecordAgent 是面向 iPhone 的独立个人数据应用。最终范围为日历、财务、资料、记录、任务五个业务模块；**首版业务模块完整对齐桌面日历，同时交付邮箱注册/登录、主界面和设置**，其余业务模块后续逐步开发。不包含聊天、模型、AgentScope、工具调用、记忆、Token 统计或桌面端运行时。界面与交互按触屏重新设计，不直接移植 React 页面。

### 首版页面流程（依据用户流程图）

```text
邮箱注册并验证 / 密码或验证码登录 → 系统主界面
```

- 邮箱作为账户登录标识。注册时填写邮箱、设置密码，由服务端发送验证码，验证通过后创建账户；后续默认用邮箱和密码登录，也支持邮箱验证码登录。两种登录方式必须返回同一个稳定用户 ID。手机与桌面必须登录同一服务端账户，才能共享日历数据；仅输入相同邮箱字符串不足以实现同步。会话管理细节仍需设计。
- 主导航为四个常驻入口：首页、日历、工作台、我的。工作台以独立目录呈现财务、资料、记录和任务，进入业务页后可返回；我的承载账户与设置。保留各业务模块的独立页面和数据语义。
- 首页采用无卡片、无分割线的连续信息流：顶部保留问候和浅色插画，原生周历支持左右分页与年月选择，中间展示选中日的四类摘要、近七日支出/专注趋势，以及可筛选、可查看详情的待办/财务/资料/记录；移除悬浮添加按钮。资料与记录分别代表资料内容和学习专注记录。
- 当前四个底部入口与工作台目录已接通：日历已改为独立自定义月格、分类标记、周/月周期便签与当天时间线，支持切月、回今天、详情、待办完成和新增待办/日程/手记；财务/资料/记录提供对应投影，任务明确显示尚未开放。当前首页数据仅在 Debug 使用标注清楚的可控样例，状态按日期保留在本次会话；Release 的真实业务服务尚未接入，展示加载失败及重试。以上不代表完整日历或其他模块已交付。
- 设置为首版必需入口，范围已定为账户信息、退出登录、多语言切换（跟随系统/简体中文/English即时生效）与日历设置（当前桌面日历的周期便签展示及默认展开等选项）；后续需求再扩展。
- “我的”以统一的浅色主体承载个人数据：有自定义背景图时全宽展示，头像、昵称和邮箱叠放其上，图片底边仅短距离渐变到主体；未设置背景图时身份区与主体同为纯净底色。未设置头像时使用豆子形象，未设置昵称时按账户稳定生成 `用户_` 加 13 位数字的展示名（英文环境为 `User_`）；全局唯一昵称须由未来服务端账户接口分配。右上角齿轮进入账户、偏好与关于设置，头像、昵称及背景图可编辑。首屏总览展示总资产、总共支出、累计学习/专注记录时长、资料数量和正文总字数、本月待办完成率，关键指标展示相较于上个月的变动对比，下方统计与活动区保持既有排版。下方“连续记录”按自然日展示最近 15 天打卡圆点刻度及连续记录天数，点选打卡圆点筛选“最近在做”，点击条目回到首页该日的原始详情；与首页共享按日服务，不另造历史数据。总资产沿用财务账户余额汇总口径，支出沿用财务分析口径；资料字数只统计资料正文，待办完成率按自然月 `已完成/总数` 计算，无待办时显示空状态。总览通过按账户及自然月读取的独立服务边界提供，Debug 样例显式标注，Release 在真实统计 API 接通前显示不可用。资料定制当前为按账户隔离的本机展示副本，编辑页提示不跨设备同步；服务端账户资料接口接通后替换服务实现。同步状态和日历偏好待对应能力接入后开放。
- 未登录、会话过期或鉴权失败时不得展示其他用户的数据，需返回登录流程并给出明确反馈。

| 模块 | 阶段与对应能力 | 现有项目依据 |
| --- | --- | --- |
| 日历 | **首版完整支持桌面日历功能**：月视图、按日详情、待办、日程、收支、手记、周期待办及便签；支持桌面端已有的创建、编辑、完成、删除与设置操作，界面按 iPhone 重设计 | `daily/`、`finance/`、`record/`、`study/` 的日历相关接口和桌面 `CalendarView` |
| 财务 | 后续：对齐桌面端账户、收支、划账、流水和统计 | `finance/` 的服务、DTO 和 Controller |
| 资料 | 后续：对齐桌面端分类、富文本、附件、回收站等资料库能力 | `record/` 的服务、文件资产与 Controller |
| 记录 | 后续：对齐桌面端“学习与专注”记录，包括时段、补录与统计 | `study/` 的服务、DTO 和 Controller；桌面 `StudyPage` 的导航名称为“记录” |
| 任务 | 后续：对齐桌面端自动任务、提醒和执行历史；研究手机系统通知渠道 | `automation/` 的服务、DTO 和 Controller；与日历待办不同 |

桌面端已有五个导航入口：日历、财务、资料、记录、任务。日历待办属于日历数据；“任务”是独立的自动任务模块，不复用 Agent 子任务。iPhone 提醒拟使用系统通知；自动任务的触发、邮件、确认和执行历史仍由服务端领域模型负责，手机通知的投递与回执方案在该模块开工前细化。

### 日历完整对齐清单

以下按当前桌面 `CalendarView`、`CalendarQuickCreate`、`CalendarDayDetails` 和日历设置梳理；实现前以最新桌面行为复核，iPhone 可调整交互形式，但需保留相同业务能力。

| 能力 | 首版验收范围 |
| --- | --- |
| 月历 | 月份切换、日期选择、每日有界标题摘要、本月待办完成数与收支摘要；完整详情按日加载。 |
| 日记录 | 查看、新增和删除待办、日程、手记；按现有桌面入口编辑支持的字段与操作。待办支持优先级、可选时间、完成切换及不重复/每日/每周/每月规则。 |
| 收支 | 从日历“记一笔”入口创建收支，查看当日收入、支出、资产变动和月度收支；保持与财务服务一致的统计口径。即使尚无独立财务页面，也须处理账户选择与无账户状态。 |
| 手记与资料 | 查看和编辑日历手记；保持与资料库每日手记的双向投影，按日展示关联资料摘要。 |
| 学习记录 | 按日展示学习时段与学习时长；独立“记录”页面留到后续。 |
| 周期便签 | 只在存在真实周/月周期待办时展示，支持完成切换、展开状态和可见性设置；iPhone 上的拖拽表现按触屏适配。 |
| 失败与同步 | 各来源按日详情独立失败与重试；写入后刷新权威服务端数据；版本冲突不得覆盖他端更新。 |

2026-09-28 界面实现：按设计图采用白底、深蓝文字、彩色月份标记、纸张胶带便签和弯曲虚线时间轴；月格左右滑动切月，时间线节点间距随实际分钟数增长且有移动端上限，曲线穿过节点中心，滚动进入的内容向上显现。时间线七种记录类型使用不同 SF Symbol，颜色只辅助辨识。首页与日历仅共享日期，日历始终显示选中日全部类型；任何日期有图片记录引用时都显示缩略封面，选中图片日期增加描边，没有图片则显示浅蓝选中态。月摘要最多返回三种类型标记及封面引用，不批量请求整月正文。便签只由周期实例生成，完成状态按周/月隔离，展开状态保存于本机；进入日历时轻微上浮，停留时缓慢小幅摇摆，离页及减少动态效果时停止。当前图片使用明确标注的内置示例资源；生产附件、日历偏好设置和完整增删改能力尚未交付。

## 2. 已确认的复用边界

- 可复用：现有领域规则、字段语义、业务测试案例和 API 契约作为设计输入。周期待办按自然日/周/月计完成，月待办落在月末；金额按最小货币单位整数存储；资料使用稳定 ID、版本号、软删除与附件 ID；每日手记在日历和资料间保持同一事实。首版先核对日历涉及的接口和跨域只读投影。
- 不能直接复用：React/Tauri 组件、CSS、Java Service 二进制或桌面 sidecar。现有数据保存在电脑的 `~/.butvan-agent/data/butvan.db` 和同级文件目录；iOS 沙盒不能直接使用这些路径。
- iOS 将通过 API 读写未来部署在服务器上的后端。现有 HTTP 接口按本机桌面应用设计，`CurrentUserProvider` 固定返回 `local-default`，桌面 API 地址默认 `localhost:8081`；部署前必须补齐身份认证、用户隔离、HTTPS、服务端数据与附件存储。iPhone 上的 `localhost` 不是电脑后端。
- 必须保留跨域语义：手记与日历双向可见；财务交易与账户余额同事务；日历收支统计与财务口径一致。移植时不能只复制页面表现。

## 3. 已确定技术栈与实现建议

| 层 | 建议 | 选择理由与边界 |
| --- | --- | --- |
| 语言与 UI（已定） | Swift、SwiftUI、Xcode | 原生触屏交互、系统导航与无障碍支持。[Apple SwiftUI](https://developer.apple.com/documentation/technologyoverviews/swiftui) |
| API（已定方向） | 服务器 API；客户端建议 Swift Concurrency + URLSession | 统一服务层处理 HTTPS 请求、鉴权、超时、响应与错误。生产环境地址集中配置。[Apple URLSession](https://developer.apple.com/documentation/foundation/urlsession) |
| 本地数据 | 暂不选本地业务数据库；仅按需缓存和临时文件 | 服务端是业务数据权威。若增加离线编辑，再设计同步、冲突与缓存迁移。 |
| 附件 | 服务端文件资产 API；本地只保存上传临时文件/下载缓存 | 业务对象只持有稳定附件 ID，不把沙盒路径当成可同步数据。 |
| 凭据与提醒 | Keychain；UserNotifications 本地通知 | 访问凭据放 Keychain；本地通知仅用于明确的设备提醒需求。[Apple Keychain](https://developer.apple.com/documentation/security/keychain-services)、[Apple 本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app) |
| 本地化与多语言 | iOS 17 String Catalogs（`.xcstrings`）+ SwiftUI Environment | 集中管理中英文字符串目录，支持无重启即时切换与动态日期/数字格式化。详见 [国际化规范.md](国际化规范.md) |
| 测试 | Swift Testing 测领域规则和 API 适配；XCTest 做关键 UI 流程 | 覆盖金额、周期日期、接口错误、鉴权失效和版本冲突；真机验证通知与附件。[Apple 测试文档](https://developer.apple.com/documentation/xcode/adding-tests-to-your-xcode-project) |

部署目标、Xcode/Swift 具体版本以开发机与计划支持的最旧 iPhone 确认后锁定；不要仅为采用新 API 提高最低系统版本。先使用系统框架，第三方依赖按具体缺口引入。财务是手工记账；不预设银行卡自动抓取或 FinanceKit。

## 5. API 数据方案与服务端前置工作

已确定采用多用户服务器 API：iOS 发起业务请求，后端执行业务规则并持久化，数据库与附件以服务器为权威。桌面端未来也要访问同一服务与用户数据；这需要改造桌面端当前的本机地址、固定用户和本地持久化方案。当前桌面端“邮箱绑定”只把资料写入本机配置，并非远程登录；部署现有后端或让两端填写同一邮箱，都不会自动完成跨设备同步。

服务器化至少需要：身份认证与每请求用户隔离、HTTPS、数据和附件的持久化/备份、环境配置、接口版本与错误语义、分页和流量限制。部署环境、数据库选型及桌面端迁移方案尚未确定；这些属于后端设计决策，不能假定现有单机 SQLite 与固定用户机制可直接上线。iOS 首版默认在线操作；离线写入若需要，另行定义同步与冲突策略。

**当前开发阶段**先完成 iOS 页面、状态、类型化 DTO、API 客户端与错误映射；使用可控假服务或测试响应演练注册/登录和日历请求，不把假服务当成实际多用户后端。真实账户联调与跨设备数据验证在服务端具备认证和持久化能力后进行。桌面历史数据迁移明确后置，见 [迁移后续事项](桌面历史数据迁移-后续事项.md)。

3. 确认最低 iOS 版本、目标设备、横竖屏范围、应用名称与 Bundle ID；首版只在用户自己的 iPhone 上安装测试，暂不安排 TestFlight 或 App Store 发布。
4. 将用户流程图细化为可操作的低保真页面流程；明确登录失败、空状态、编辑、删除、无网络、鉴权失效和冲突反馈。其他业务模块只记录后续范围。
5. 从现有日历 Java DTO 和 TypeScript 类型整理 API 字段对照表；核对日期/时区、周期待办、版本号和每日手记投影。
6. 用可控假服务验证日历查询、写入、版本冲突、登录失效等客户端路径；待服务端具备认证、隔离和 HTTPS 后再联调真实账户与数据。其他业务模块的验证留到对应阶段。
7. 建立 Xcode 工程、测试目标和格式/静态检查；完成一条纵向流程（邮箱登录→首页→日历→新增待办→完成），再扩展日历与设置其余能力，并在用户自己的 iPhone 上验证。
