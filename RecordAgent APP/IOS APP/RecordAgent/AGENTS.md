# RecordAgent iOS 工程约束

本文件适用于当前目录及其子目录，叠加仓库根目录 `AGENTS.md`。修改文件前先读取两者；产品范围和未决事项见 [开发前规划.md](开发前规划.md)。

## 产品与技术栈

- 使用 Swift、SwiftUI 和 Xcode 开发原生 iOS App，首版只覆盖日历、财务、资料、记录、任务。Agent、聊天、模型和桌面运行时不进入本工程。
- 由 SwiftUI 视图负责展示和交互，领域层负责业务规则，服务层负责 API 请求、响应解析和错误映射。视图不直接拼接 URL 或调用 `URLSession`。
- 沿用现有后端的业务语义和稳定 DTO；新增或改变接口时同步维护后端 DTO、iOS 模型与接口文档。iOS 不复制 Java 业务服务，也不直连后端数据库。

## 数据与服务端边界

- 后端未来部署在服务器上；iOS 以 HTTPS API 作为业务数据的权威读写入口。API 基础地址按环境集中配置，生产地址不能硬编码在视图中。
- 身份认证、用户隔离和安全传输须在接入真实服务器前完成。现有 `CurrentUserProvider` 固定用户及本机 `localhost:8081` 仅适用于桌面开发，不能直接用于公网部署。
- 本地存储只用于明确设计的缓存、临时文件和必要的凭据；缓存不是业务权威，离线写入与冲突处理须有单独方案后才能启用。访问令牌等敏感凭据使用 Keychain，不写入源码、日志或普通偏好设置。
- 财务金额按最小货币单位整数传输；日期、时间与 IANA 时区分别处理；更新请求携带服务端要求的版本号。附件按服务端稳定文件 ID 关联，上传与下载走受控 API。
- 任务含义、记录与资料的关系以产品决策为准；在明确前不创建第二套待办或手记数据事实。

## 开发与验证

- 目录按 `App/`、`Features/`、`Domain/`、`Services/`、`DesignSystem/` 分责；具体结构在创建工程时依据实际规模调整。
- 对金额、周期日期、时区、版本冲突、响应错误和附件流程补充必要测试；涉及 API 的功能使用可控假服务验证，真实服务联调另行执行。
- 新增系统权限时按实际功能最小申请，说明用户收益；通知授权只在用户启用提醒时请求。
- 完成修改后执行最贴近的 Xcode 构建、测试或静态检查，记录未验证范围，并遵守根目录提交与工作区保护规则。
