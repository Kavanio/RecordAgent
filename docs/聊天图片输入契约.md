# 聊天图片输入契约

## 支持范围

桌面端点击输入框「+」选择图片或粘贴截图，可仅发图片，也可附文字或直接引用资料；图片暂不与斜杠命令、业务分析命令一起发送。飞书只接收本人私聊的纯图片消息，图文混排（post）明确提示分开发送，不截取第一张图并覆盖用户正文。

发送前检查所选模型的 `supportsVision`。桌面端本地提示不支持时保留草稿；后端在解码前检查，并在通用 `AgentService` 注册运行前再校验。飞书在受理和排队结束下载前分别检查。模型配置标注只是用户声明，不保证供应商实际支持视觉输入。

## 大小边界

- PNG、JPEG、WebP、GIF；前端 MIME 缺失时可按扩展名提示，后端始终按文件头判断。
- 单张不超过 10 MiB，每轮最多 4 张，原始字节合计不超过 12 MiB。
- HTTP JSON 请求体不超过 17 MiB：12 MiB 图片的 Base64 约为 16 MiB，剩余预算供文字与 JSON 包装使用。
- `ChatRequestSizeAdvice` 限制 Jackson 读取的实际流字节，即使缺少或伪造 Content-Length 也生效；不调整全局 multipart 额度。
- 单张编码长度和整轮预测解码长度在创建字节数组前检查，解码后复核实际格式与大小。超限拒绝，不截断、不自动压缩。

## 桌面接口

`POST /agent/chat/stream` 继续使用原有 API Token 和当前用户权限边界，JSON 增量字段：

```json
{
  "runId": "稳定运行 ID",
  "sessionId": "当前会话 ID",
  "content": "请描述图片",
  "context": "请描述图片",
  "recordReferenceIds": [],
  "images": [{ "mediaType": "image/png", "dataBase64": "不含 data URL 前缀的 Base64" }]
}
```

`images` 可省略；空正文的图片请求由后端补可读说明。图片数据不进入应用 transcript、checkpoint、渠道账本或日志；图片持久化和历史原图展示未在本次实现。

业务校验沿用统一 Result（业务 `code=400`，HTTP 可能为 200），客户端先识别 JSON 校验响应再解析 SSE，展示中文拒绝原因。JSON 请求体超过实际字节上限返回 HTTP/业务 `413`。权限恢复请求不重新携带图片。

## 草稿行为与验证

图片草稿按 `sessionId` 隔离；切会话、清空、卸载后丢弃迟到的文件读取，连续选择串行追加而非覆盖。读取期间 Enter 和发送按钮均不可发送；移除图片不影响正文。发送与资料引用组合时也清空已消费图片。

自动测试覆盖纯图片发送、视觉能力拒绝、Base64/文件头/数量/总量限制、HTTP 实际字节上限、飞书 post 拒绝、排队后切模型、连续粘贴及跨会话迟到读取。前端统一通过 `pnpm --dir agent-frontend test`、`lint`、`build` 验证；真实供应商与飞书联调另需授权。

后端需要重编译时，应在临时副本或隔离输出目录验证；不要清理或覆盖正在运行的 IDEA 后端所用 `target/classes`。
