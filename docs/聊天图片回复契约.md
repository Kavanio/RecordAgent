# 聊天图片回复契约

## 使用方式

- 对话里发送「截一下当前电脑主屏幕发给我」，核对审批卡后允许一次。截取的是当前会话所连接的后端宿主电脑。桌面端连接远程 Windows 后端时，截图目标是该 Windows 电脑。要截 Mac 屏幕，客户端须连接在该 Mac 的登录桌面运行的后端。
- 说「找三张日式庭院的图片发给我」，Agent 使用现有 Tavily 凭据调用图片搜索。图片可点开、放大、保存。网络图片可打开原图地址。
- Windows 和 macOS 的桌面端通过系统面板选择存放位置。iOS 从大图菜单存储原图到「文件」，也可以通过系统分享面板分享图片。截图和找图都支持纯文本模型。

## 启用宿主截图

截图默认关闭。可在运行后端的用户主目录 `~/.butvan-agent/` 下创建空文件 `screen-capture.enabled`，移除该文件即关停本地开关。也可设置 `BUTVAN_SCREEN_CAPTURE_ENABLED=true` 并重启后端，Windows 原生 BAT 部署使用 `data/backend.env`。任一开关开启即可使用。

- Windows 使用宿主的 Windows 图形会话，支持仍连接且未锁定的会话。服务会话、断开的 RDP、锁屏和 UAC 安全桌面返回失败。
- macOS 使用系统截图程序。登录桌面内的后端还需要「系统设置 → 隐私与安全性 → 屏幕与系统录音」权限。为实际启动后端的应用启用后，按系统提示重新打开该应用或重启后端。锁屏、切换到其他用户或缺少屏幕录制权限时返回失败。

## 运行和接口

- `capture_screen` 为无参数的单帧主屏工具。审批绑定原 `runId`，即使会话处于完全访问也要求明确允许，且不能记住授权。同轮最多执行一次采集。工具仅在拥有当前受信任对话运行上下文时执行。
- `web_image_search` 接受 `query` 和可选 `count`（1–4，默认 3），从 Tavily 返回的图片候选获取公开 HTTPS 位图。下载器仅连接通过检查的公网地址，限制端口、时间与字节，拒绝重定向。返回成功导入的图片，失败候选不会进入消息。
- 图片均经文件头校验，单张 10 MiB，最多 4 张，每轮合计 12 MiB。图片字节先保留在当前运行内存，成功终态通过对话档案归档。终态前取消或失败时没有持久化的图片回复。模型上下文、检查点和 SSE 不含截图或联网图片字节。
- `GET /agent/sessions/{sessionId}` 的助手消息可选 `replyImages: [{fileId, title, sourceUrl}]`。终态 SSE 先写 transcript 再发 `done`，客户端按现有流程同步该会话详情。旧会话与旧版本后端允许缺少字段。
- `GET /agent/materials/{fileId}/content` 继续通过 API 鉴权和档案所有者校验读取原图。客户端使用认证请求头。图片删除后，历史里的原文件引用会显示加载失败。截图查看与归档限于当前单用户部署；历史和重置沿用对话档案的保留语义。

## 验收

在 Windows BAT 后端和 macOS 本机后端分别从桌面端或 iOS 发起请求，确认允许一次后看到主屏图，刷新仍可打开，保存得到可读文件。拒绝、锁屏、断开 RDP 和 macOS 权限未授予时无图片附件。找图用真实 Tavily 凭据验证有效结果、打开原图和来源站点失效后的已归档回显。
