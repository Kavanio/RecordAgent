# 长期复盘接口与使用说明

## 状态与范围

已实现：配置／独立授权、已结束自然日事实摘要、用户明确目标、模型结构化草案生成、建议与观察反馈、邮件两段式冻结，以及设置页的开启、授权、预览、历史和反馈。

使用前提（缺一不可）：开启长期复盘、选择固定模型连接、显式勾选同意并授权、报告任务本身开启邮件。未授权时不会调用模型；未开启邮件的报告不生成 AI 内容。

设置响应的 `enabled` 是保存的偏好，`authorized` 表示范围与接收方当前是否仍被授权；`generationAvailable` 目前仍返回 `false`，表示不存在“无需确认即可后台调用”的公开开关，所有生成都必须先有明确授权。模型固定为授权时选择的那一个连接，不跟随聊天默认模型切换。

存储使用当前后端的 `~/.butvan-agent/data/butvan.db`，V22 新增 review 领域表。本机后端数据在电脑，远程后端数据在服务器。测试仅使用临时目录。当前没有引入 Mem0／Letta 或其他第三方依赖，开源设计参考仍见[实施方案](自动长期记忆复盘教练实施方案.md)。

## 统一协议

- 路径前缀 `/agent/reviews`；复用应用 Token／CORS 和当前单用户保护措施。owner 只来自 `CurrentUserProvider`，不接受客户端提供。
- 成功为 `Result<T>`：`{ "code": 200, "message": "...", "data": ... }`。业务校验、缺失资源、范围错误、版本冲突或失效授权当前均返回 `code=400`；数据来源全部不可用返回 `code=503`。沿用既有 ApiExceptionHandler，不保证业务 code 等于 HTTP 状态。
- Controller 全部带 ApiLog；日志仅记录参数类型与结果摘要，不记录目标、模型 Key、财务正文。Key 不写入 review 表，也不在响应中返回。
- 所有写请求都不由前端服务层自动重试。客户端应在失败后读取状态，不能假定网络断开表示写入没有完成。

## 已实现接口

| 方法／路径 | 输入 | 响应与校验 |
| --- | --- | --- |
| `GET /settings` | 无 | SettingsView；首次读取返回 revision=0、enabled=false、authorized=false，不写库／不初始化模型配置 |
| `PUT /settings` | expectedRevision、enabled、periods、domains、historyDays、dailyLimit、providerId、modelName | 新 SettingsView；保存不是授予权限；旧 revision 拒绝覆盖 |
| `POST /grants` | expectedSettingsRevision、policyVersion、confirmed | GrantView；confirmed 必须为 true，版本必须为 report-review-v1；新授权撤销旧有效授权，保留审计 |
| `POST /grants/{id}/revoke` | expectedRevision（授权 revision） | 撤销后的 GrantView；不删除历史，但阻止后续摘要采集 |
| `POST /facts/capture` | from、to（YYYY-MM-DD）、timezone（IANA 时区） | SnapshotView；需 enabled 且当前授权有效，只在本地采集，不调用模型 |
| `GET /facts?limit=20` | limit：1–50 | 当前用户未过期快照的轻量元数据，单查询读取，明细按 ID 加载；不触发采集 |
| `GET /facts/{id}` | 快照 ID | 既有不可变 SnapshotView；其他用户／不存在／过期均按无效资源处理 |
| `GET /goals` | 无 | 当前用户目标列表，最多 100 条；包含归档状态 |
| `POST /goals` | expectedRevision=0、title、constraintText、successCriterion、state | GoalView；最多 3 个 ACTIVE，目标总量最多 100 |
| `PUT /goals/{id}` | 上述字段，expectedRevision 为旧 revision | 新 GoalView；state 为 ACTIVE／ARCHIVED，拒绝跨用户或旧版本更新 |
| `POST /erase` | expectedSettingsRevision、confirmed=true | 撤销授权、关闭设置并清除本用户摘要／目标；同时禁用未冻结的 AI 邮件副本 |
| `POST /preview` | requestId、period、from、to、timezone、confirmedPaidCall=true | 调用一次已授权模型，返回结构化结果；不发送邮件、不保存长期建议 |
| `GET /agent/reviews?limit=20` | limit 1–50 | 复盘历史摘要，按创建时间倒序 |
| `GET /agent/reviews/{id}` | 复盘 ID | 结果、覆盖说明、观察／跟进／建议与依据；不重新调用模型 |
| `GET /agent/reviews/memory` | 无 | 建议与未过期观察列表 |
| `POST /agent/reviews/actions/{id}/feedback` | requestId、expectedRevision、decision、可选标题／标准／检查日／说明 | 幂等；结果类反馈必须先采纳 |
| `POST /agent/reviews/observations/{id}/correction` | requestId、expectedRevision、CORRECTED／REJECTED、说明 | 纠正或否定后不再作为召回证据 |

periods 非空且仅允许 DAILY_REPORT／WEEKLY_REPORT／MONTHLY_REPORT；domains 非空且仅允许 FINANCE／TODO／STUDY；historyDays 为 1–180，dailyLimit 为 1–3。上限目前只作为配置与授权范围保存；没有模型执行器，所以尚不存在实际调用计数或预算消耗。

固定模型必须是已保存且开启的 Provider ID、该连接登记的 Model ID。协议／地址指纹由服务端计算，不接受客户端提交“可信指纹”。修改接收方、扩大数据域／周期、窗口或每日上限后，旧授权不覆盖新配置；缩小范围可继续使用。模型 Key 轮换不改变指纹，模型配置缺失时授权视为无效，但仍允许用户暂停已有配置。

目标标题最多 200 字符，约束最多 500，完成标准最多 300；标题必填。目标仅由用户创建，不自动同步画像，不从事实摘要推断目标。归档目标仍可读取与更新，当前显式删除采用 `/erase` 全量清除路径。

## 摘要口径与隐私

单次最多 7 个已结束自然日，起始日在授权 historyDays 范围内；当日、未来、倒置、无效时区或超长窗口均拒绝。当前不支持当天截至生成时的 partial 窗口；该能力及与基础报告共享 cutoff 的改造属于后续 P1 工作。

- FINANCE：经 FinanceService 与 ExpenseAnalyticsService 汇总真实收入（含已入账收益）、支出、结余、按稳定账户 ID 回溯的期末余额；初始资金、划账和校准不算收入。旧日历支出按既有投影参与支出，不重复计数。不同币种不折算。
- TODO：仅经 `DailyEventService.getTodoOccurrences` 读取所属用户的待办 ID、重复周期与完成状态；在 SQL 层限制用户和待办类型，共用日历发生规则，不查询财务投影或加载手记／资料正文。按一次性／日／周／月发生周期去重，保存应办与已完成数量，不保存标题；财务来源失败不影响待办采集。
- STUDY：读取学习 Service 的时长秒数、记录数与有学习记录天数，不保存内容或地点。
- 不保存账户名称、订单备注、完整流水、聊天／资料正文。接口不是邮件文本的反向解析器。
- 任一域失败只标记该域 UNAVAILABLE，丢弃该域中间结果；其他域继续。无记录标记 EMPTY，不等同于接口不可用。全部域失败不保存空快照。

每个 Fact 包含 domain、metricKey、subjectId、currency、unit、value。数据库 value 为 64 位整数；HTTP 的 value 为十进制字符串，例如 `"1234"` + `MONEY_MINOR` + `CNY` 表示人民币 12.34 元，避免前端丢失大整数精度。unit 还包括 COUNT／SECONDS。

快照保存日期范围、时区、sourceAsOf、metricVersion、内容指纹与 expiresAt。sourceAsOf 表示此次采集，不表示历史数据从未修改。账户余额为当前账本回溯，不是历史账户快照；已删除账户缺少档案时不能还原。已完成周期的待办和其他历史记录也可能因后续修改而变化，因此来源指纹只能表明本次结果，而不能证明历史行为因果关系。

重复采集同范围／时区且内容不变时复用快照；补录后结果变化则新增版本，旧版本不改写。采集在写事务外进行，写入前重新校验授权 ID、revision 与配置 revision，撤销／清除／改范围期间的采集不能继续落盘。

## 清除与保留期

`POST /erase` 只清当前用户的 review 摘要和目标，保留最小授权审计与关闭后的配置，不删除模型配置、聊天画像、真实账本或自动任务历史。清除使进行中采集失效，需要新的明确授权才能再次采集。

当前快照过期后查询不可见，下次该用户采集时物理清除；也可以显式清除。**后台定期保留期清理尚未完成**，在后续自动评审上线前必须补齐。关闭开关本身不会删除数据。后续 AI 邮件快照删除规则将按实施方案单独实现，本阶段不能承诺已支持。

## 验证与阶段限制

- 后端使用 ReviewFoundationIntegrationTest（临时 SQLite、fake 领域来源与模型身份）和 ReviewModelCatalogTest（临时模型配置）；不读取真实配置、不调用远程模型。ReviewTodoIsolationTest 使用真实 DailyEventService 验证仅 TODO 的调用链不访问全量日记录、其他类型详情或财务 Service，并验证财务故障隔离、周期去重与缺失详情降级。DailyEventServiceIntegrationTest 使用临时 SQLite 对比新旧查询在一次性、日、周、月、旧周期规则与用户隔离上的一致性。
- 复盘基础、现有自动任务、财务及日记录 Service 相关测试共 93 项通过。额外 FinanceApiIntegrationTest 的旧断言把固定 2026-09 收入用于当前月图表，在当前日期失败，未修改此无关用例。额外 DailyEventApiIntegrationTest 有两条既有断言失败（周期便签生效日期、未指定月发生日的旧规则）；已用修改前的 DailyEventService／Repository 在独立临时目录编译复现，不将其算作通过，也未顺带改变现有行为。
- 前端 `pnpm test:reviews` 6 项通过；`pnpm exec tsc -b` 与新增前端文件 oxlint 通过。没有新增 UI，因此 UI COMPONENTS.md 不变，也未做截图或手工浏览器验收。
- 前端只有 types/review.ts 与 services/reviewApi.ts，不会自行发请求，没有可误开启的界面开关。全部真实用户模型授权和数据仍未创建。
