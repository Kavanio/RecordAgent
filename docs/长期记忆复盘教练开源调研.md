# 长期记忆复盘教练：开源调研与融合建议

> 后续用户已选择自动模式，具体规划以[自动长期记忆复盘教练实施方案](自动长期记忆复盘教练实施方案.md)为准。本文保留调研阶段“手动优先”的历史建议；自动财务处理的授权例外仍未生效，当前没有启用任何模型调用或上传。

## 结论与核查范围

用户期望的是持续理解个人目标、回看历史、跟踪建议结果的复盘教练，而不是单次邮件润色。可以融合现有项目，但记忆检索并不自动带来可靠建议：还需要业务数据校验、用户反馈、反证与效果追踪。

本次核查官方仓库、作者文档和论文，并检查当前项目依赖与上下文入口。没有运行候选项目，也没有完成安全审计、依赖审计或真实效果评测；不能把 README 功能声明当作验证通过。上游 main 和在线文档会变动，正式引入前必须锁定版本与提交，再核查许可证及传递依赖。

## 推荐的本项目方案（待实现）

### 不是保存全部聊天，而是四层可追溯记忆

1. **事实层**：报告统计、数据范围、来源 ID、生成时间与缺失情况。流水和业务记录仍是事实来源，模型不负责算账。
2. **用户确认层**：目标、约束、偏好、当前实验；用户可改、可撤销，不由 AI 推测的人格标签替代。
3. **观察层**：多日／多周重复现象，包含样本范围、证据、反例、置信度、过期时间；AI 推断与用户陈述分开。
4. **建议与结果层**：建议 ID、具体动作、采用／拒绝／未反馈、检查日期、实际结果。没有反馈不等于未执行，没有改善也不能直接推断建议无效。

日报参考近期 7／28 天及相关历史；周报参考近 4／12 周；月报参考近 3／6 月。这些是候选窗口，不是强制读取全量数据；数据不足要说明。跨周期指向同一建议 ID，避免日报、周报重复开出同样建议或重复计算成果。

### 执行闭环

```text
业务事实与当期报告
  → 查询已确认目标、相关历史、未完成建议
  → 按时间／来源／相关性检索，去重并施加 Token 硬预算
  → 数据规则检查（完整性、币种、资产变动与收支的区别）
  → 模型生成：事实观察／不确定解释／小步实验
  → 校验引用、数字、结构、禁止内容与长度
  → 展示或冻结邮件
  → 用户确认是否采用
  → 下次检查结果，更新观察或生成待确认提案
```

每条建议要能回答：依据是什么、为什么适合当前目标、是否已经建议过、下一步多小、何时检查、什么结果会推翻这条建议。缺证据时优先提问或不提建议，不用第二个模型的同意充当事实验证。不能承诺所有建议始终正确。

### 与现有代码边界衔接

- `server-network/automation` 负责报告与投递；业务事实经财务、学习、日记录等公开 Service 获取，持久事实属于对应业务域，不跨层直接查库。
- `server-agents` 负责模型与编排，复用 `ModelFactory`，不反向依赖业务实现。
- 当前已有 `ConversationContextAssembler` 管理有界个人上下文。新增复盘记忆来源必须评估并接入这一唯一上下文 seam，不能另起一个无限注入历史的通道。
- AI 观察不自动写入用户画像；画像修改继续遵守来源、revision 校验与用户确认规则。复盘模块不覆盖聊天 MEMORY.md。
- 首版可使用现有 SQLite 保存领域化复盘记录、按时间与标签检索；语义检索确有收益后再接 Mem0 等 Adapter，不急于增加 Python 服务或第二套 Agent 平台。
- 评审失败不阻断基础报告；冻结结果后重发不重新评审。记录模型版本、输入来源、用量与评审版本，支持回归测试。

## 从自我提升书籍获得方法，而不是拼接金句

- 《Atomic Habits／掌控习惯》：将注意力从结果转向可重复执行的系统与小步改变。可转为检查“任务过大、开始阻力、环境提示”的问题，而不是简单指责自律不足。[作者关于目标与系统的文章](https://jamesclear.com/goals-systems)、[作者书籍摘要](https://jamesclear.com/atomic-habits-summary)。
- 《Thinking in Bets／对赌》：区分决策质量与一次结果，保留不确定性。可转为记录假设与后续证据，不因为一周表现变差就否定方法。[作者关于决策与结果的讨论](https://www.annieduke.com/making-better-decisions-by-thinking-in-bets/)。

可以自写小型方法卡：适用条件、提问、实验步骤、限制、来源。不要未经许可导入整本受版权保护的书，也不要把书中观点当作已对该用户验证的结论。产品定位为自我反思辅助，不进行心理诊断或人格评分。

## 授权与验证

当前工程契约要求包含财务数据的 AI 分析逐次确认；本次调研不变更此规则。因此先做用户触发的长期复盘预览，不能静默开启自动财务评审。未来若要定时自动评审，需另行明确授权与撤销机制、模型数据去向，并同步工程契约。

验证至少覆盖：事实引用正确、历史检索隔离、记忆冲突与过期、用户纠正、未采纳建议不算失败、重复建议去重、日报／周报／月报一致性、授权撤销、模型超时降级、幻觉数字拒绝、邮件快照不变与 Token 上限。

本次只产出调研文档，未引入第三方依赖、部署服务、调用模型或启用任何个人数据上传。
