# server-network 工程约束

本目录承载 Spring Boot 组合根、HTTP 协议适配和单机业务数据的 SQLite 持久化。除根目录 `AGENTS.md` 外，修改本模块还必须遵守以下规则。

## Agent 业务工具

- 日历、财务、资料和学习等业务 Agent Tool Adapter 归属本模块，通过对应领域 Service 复用业务规则；不得调用 Controller、绕过 Service 直接访问 Repository，或在 Tool 中复制领域校验。
- `server-agents` 只提供 Tool 注册 seam 与通用执行契约；业务 Tool 通过该 seam 自动注册，禁止为注册业务 Tool 建立 `server-agents` 到 `server-network` 的反向依赖。
- Tool 不接受调用方传入的 `ownerId`，必须通过 `CurrentUserProvider` 获取当前用户；读取 Tool 才能加入安全白名单，任何业务写入在非完全访问模式下都必须进入统一确认流程。
- 业务写 Tool 使用 `agent_tool_operation` 保存按用户、Tool 名称和幂等键隔离的执行结果，并与领域写入处于同一事务；该表只用于防止重复执行，不得成为业务事实来源。

## 本地数据库

- 业务数据库固定存放于 `~/.butvan-agent/data/butvan.db`；测试必须覆盖路径并使用临时目录，禁止触碰用户真实数据。
- 数据库结构只允许通过 `src/main/resources/db/migration/` 下的 Flyway 迁移演进；已发布迁移不得修改，只能新增更高版本迁移。
- SQLite 数据源统一由 `config/database/` 创建，必须启用外键、WAL 与锁等待；前端、Tauri 和其他进程不得绕过后端直接写库。
- 金额按最小货币单位整数存储；日期、时间、时区分别表达；日志不得输出手记正文、完整财务内容或其他敏感业务数据。
- 数据表按业务域归属。跨域读取必须经过领域 Service，禁止 Controller 或其他模块直接拼接 SQL 查询别的领域表。

## 文件资产

- `file/` 是通用文件资产模块：`FileAssetService` 统一维护所有权、业务绑定、大小限制、状态和内容生命周期；业务域只保存或传递稳定文件 ID，不得拼接本地路径、Bucket、Object Key 或第三方 URL。
- 二进制内容必须通过 `BlobStore` seam 读写。本地 Adapter 将新对象保存于数据库同级的 `files/objects/`，写入必须经过 staging、实际字节上限校验、SHA-256 计算和原子移动；数据库只保存元数据，不保存大文件内容。
- `file_binding` 使用后端受控的 `domain_type` 与 `role`。读取、下载、解绑前必须同时校验 owner、业务对象和文件 ID，禁止只凭可猜测的文件 ID 访问内容。
- 新增第三方存储时实现独立 Adapter，不得把供应商 SDK 类型泄漏到 `FileAssetService` 或业务域；访问密钥只允许通过专用凭据存储引用，禁止进入 SQLite 文件资产表、接口响应和日志。
- 文件系统、SQLite 与第三方对象存储不具备共同事务；失败路径必须保留可追踪状态并清理临时内容，禁止先丢失元数据再删除实际对象。
- 本地账户头像使用 `ACCOUNT / AVATAR` 文件绑定；上传端必须校验真实图片格式、尺寸和实际字节数，只允许受控图片类型，替换成功后再回收旧头像。

## 日记录

- `daily_event` 只保存所有日记录共有字段；待办、日程、花销、手记及未来学习记录等类型使用独立详情表。
- 可检索、筛选、统计或参与约束的字段必须建正式列；`extension_json` 仅保存低频、未稳定的扩展信息，禁止替代正式业务模型。
- 新增日记录类型必须提供类型处理器、详情迁移、类型化请求 DTO、前端降级展示和公开接口测试，不得修改已有类型详情表来塞入无关字段。
- 核心记录与详情必须在同一事务内写入；修改和删除必须检查所有者，覆盖写入使用版本号避免静默丢失更新。
- 待办支持不重复、每日、每周、每月四种周期；每周待办必须保存 ISO 星期（1 表示周一、7 表示周日），每月待办统一以 31 作为月末规则标识，并按自然月实际最后一天发生。周期待办按自然日、周一开始的自然周或自然月分别记录完成状态。
- 月历摘要中的每日与每周待办不得提前投影到未来日期；每月待办创建后必须投影到当月及后续自然月的最后一天。待办完成率只统计截至今日已生效的待办；当日详情按一次性、每日、每周、每月的顺序展示。
- 日程开始时间与结束时间均为可选；仅在两者同时存在时校验结束时间晚于开始时间，前端不得用虚构默认时间替代未知时间。

## 财务记录

- `finance/` 独立承载资产账户、收入、支出与收益计提；日历不直接修改财务表，但日历摘要与按日详情必须通过只读收支分析 Service 合并历史花销、财务支出和财务收入。
- 每条手工收支必须关联一个归属当前用户的资产账户，并在同一事务内写入流水、调整余额；支出不得造成负余额。
- 单条手工收入与支出允许修改账户、类型、分类、说明、金额和发生时间；保存时必须在同一事务内撤销原流水对原账户的余额影响，再把新流水影响应用到目标账户，任一账户余额校验失败时整体回滚。自动收益、成对划账与旧日历花销不得通过单笔流水编辑入口修改。
- 流水删除必须通过 `DELETE /agent/finance/transactions/{transactionId}`，在同一事务内按原方向回滚账户余额后物理删除行：手工收入与支出、余额校准可删，撤销后会造成负余额时拒绝；划账通过 `finance_transaction.pair_id` 成对删除并同时回滚两侧账户；`yield` 自动收益禁止删除，只能通过调整账户年化率修正；旧日历花销不存于财务表，必须转交日历领域 Service 删除，保证日历、资料与财务列表同时消失。
- 资产账户允许通过余额校准手动增加或减少，必须填写备注，并在同一事务内调整余额、写入带独立类型和来源标识的校准流水；校准流水只用于审计余额变化，不得计入真实收入、支出、收益、日历收支或趋势统计，手动减少不得造成负余额。
- 新建账户分类统一使用微信余额、微信零钱通、支付宝余额、支付宝余额宝、银行卡与其他；已保存的 `wechat`、`alipay`、`cash` 旧类型继续只读兼容。
- 生息账户以用户填写的当前年化率按 365 天逐日复利估算，查询财务总览或新增流水前补齐至当日；自动收益使用唯一日流水防止重复入账，并计入收入统计。
- 财务金额继续按最小货币单位整数保存；收益率使用独立正式列，自动流水必须保留可识别的 `source`。
- 财务月支出、日历月支出和支出图表必须复用同一跨域只读投影；图表接口提供连续日期、每日支出总额、支出分类金额与每日收入总额，避免前端分别计算形成口径漂移。
- 月历月度结余通过 `GET /agent/finance/cashflow-summary?from=YYYY-MM-DD&to=YYYY-MM-DD` 读取当前用户闭区间收支，返回 `{ income, expense }`，排除划账和余额校准并包含旧日历花销；非法、倒置或超过 366 天的日期跨度按参数错误处理，空区间结果为零值。该只读接口统计已入账流水，不触发收益补计，也不加载整月流水明细。
- 财务“最近流水”需按时间合并财务流水与旧日历花销；旧日历花销只做兼容展示，不得反向绑定或修改资产账户余额。
- 财务首页总览仅承担最近流水；完整历史由 `GET /agent/finance/transactions` 按需读取，响应沿用 `TransactionResponse` 列表并包含账户、分类、来源、日期与时间。
- 财务支出分析由 `GET /agent/finance/expense-insights?range=week|month|year` 按当前用户返回自然周期起日至今的账户支出、金额降序的全部单笔支出、完整分类合计及全口径支出总额；非法范围按参数错误处理。`accounts[].amount` 为账户支出，`accounts[].income` 为收入（`income` 与 `yield`），`accounts[].accountType` 为账户类型，供前端稳定识别账户品牌；读取前补齐收益，账户图支持收支切换。两项均排除划账和余额校准；旧日历花销仅进入支出单笔与分类排行。响应仅返回排行所需字段，不透传完整流水对象。
- 收入与支出分类分别维护内置选项和用户使用过的自定义选项；成功创建流水时自动记住分类，两个类型之间不得混用自定义分类。
- 分类颜色保存于 `finance_transaction_category.color`，按当前用户、收支类型和分类名称隔离。`GET /agent/finance/categories` 保留 `expense`、`income` 名称列表并返回 `colors: { expense: { 分类名: "#RRGGBB" }, income: { 分类名: "#RRGGBB" } }`；`POST /agent/finance/transactions` 和 `PUT /agent/finance/transactions/{transactionId}` 接受可选 `categoryColor`，仅六位十六进制颜色有效，非法值返回统一参数错误 `code: 400`。颜色与流水、余额在同一事务保存，省略或 null 保留已有颜色；未配置颜色由前端按分类名称稳定分配，`GET /agent/finance/expense-chart` 同次返回支出 `categoryColors`，避免独立分类请求迟到或失败造成配色闪变；切换图表区间不得改变颜色。

## 学习记录

- `study/` 独立承载学习时段的开始、结束、补卡、修改、删除与时长统计；学习时段同时作为 `study` 类型日记录写入 `daily_event`，专属字段保存在 `study_session_detail`。
- 同一用户最多存在一个进行中的学习时段；结束时间必须晚于开始时间，已结束时段不得相互重叠，所有写入必须在同一事务内维护公共记录与学习详情。
- 学习时长由后端根据时间点计算，前端不得提交或持久化计算后的时长；跨自然日时按学习时段记录的时区拆分到每天，保证日、周、月统计口径一致。
- 项目内开始、补卡及未来快捷指令都是学习模块的输入适配器，必须复用同一领域校验与统计接口；来源使用稳定枚举值，不得根据文案推断。
- 学习分类支持内置选项和用户自定义输入；开始、补卡或修改成功时自动记住分类，后续录入必须可再次选择。
- 学习状态通过用户级 SSE 实时同步：领域写入必须在事务提交后发布变更事件，订阅建连及自动重连时必须发送当前活动时段的权威快照；前端不得对活动学习接口进行定时轮询，断线期间遗漏的状态只通过重连快照恢复。

## 每日洞察

- `insight/` 只通过各领域公开 Service 组合日历、资料、财务与学习的只读统计，不得跨域拼接 SQL，也不得在查询时调用模型。
- 每日洞察以调用方提供的自然日和 IANA 时区为准；Slash Command 只负责触发和展示，不得在前端重复推导统计口径。

## 天气与节假日

- `dailycontext/` 负责聊天顶栏所需的天气与节假日外部数据适配；Controller 只暴露脱敏配置和稳定摘要 DTO，第三方响应结构不得直接透传前端。
- 和风天气请求只允许访问用户配置的 `*.qweatherapi.com` 专属 Host，保存配置和实际发起请求前都必须校验目标；天聚数行密钥使用请求体传输，两个供应商的密钥均不得写入日志、URL 或响应。
- 天气与节假日必须独立降级并按合理 TTL 缓存；任一供应商失败不得阻断另一项或聊天主流程，未启用的模块不得触发第三方请求。
- 设备定位只能在用户主动操作后请求前台权限；坐标可通过和风 GeoAPI 反查展示名称，但必须先回填表单，只有用户确认保存后才能持久化。
- 和风控制台财务与请求量数据仅供设置页按需查看；必须复用本机凭据、保持财务与统计接口独立降级并设置短期缓存，响应只返回稳定汇总，不得透传账单编号、凭据或第三方原始结构。凭据未开启控制台权限时必须提供可执行的权限指引。

## Token 用量

- `token_usage_turn`、`token_usage_invocation` 与 `token_usage_tool` 是统计读模型；聊天 transcript 与系统用量 JSONL 是权威数据源，统计查询必须允许安全重建 SQLite 投影。
- 聊天轮次与非聊天调用分开建模；全局统计可以合并展示，但不得把会话标题等系统用途计入聊天轮次。
- 日期筛选使用应用所在时区的闭区间自然日；供应商未上报的实际用量保持不可用，不得通过字符数估算补齐。
- 输入分类与逐工具 Token 是本地估算投影，必须携带计数器版本并与供应商实际输入分开表达；个人画像与相关记忆必须独立归因，信封标签等包装开销继续归入 RAG Context；估算误差不得反向改写实际输入、输出或缓存 Token。

## 聊天上下文适配

- 聊天图片在 Base64 解码前检查视觉能力、数量、单张编码长度与总预算，解码后按文件头复核；`ChatRequestSizeAdvice` 在 Jackson 反序列化前限制聊天 JSON 的实际输入流，不以 Content-Length 或 multipart 配置代替。业务分析命令与图片不兼容时明确拒绝，不得静默丢弃附件。

- 稳定资料 ID 必须在 `chat/` 内校验所有权与可引用状态后再读取正文；前端不得自行展开资料正文，也不得提交可伪造的 RAG Token 归因。
- 画像辅助维护接口归属 `context/`，只允许操作 `CurrentUserProvider` 解析出的当前用户；检查接口只生成唯一待审核提案，确认接口必须校验画像 revision，拒绝接口不得修改当前画像。
- 用户可见命令与模型上下文分开传递，Transcript 只保存用户可见内容；实际送入模型的资料片段必须登记为 `RAG Context`。
- AI 分析命令只允许前端提交受控命令、范围、时区和逐次确认状态；业务数据必须由后端按当前用户读取、最小化后作为独立 `RAG Context` 注入。凡包含财务数据的命令都必须在每次请求中显式确认，不得持久化或复用同意状态。

## 长期复盘运行

- `review/` 的授权、事实、目标、建议和邮件冻结是同一业务域；生成使用用户显式授权时冻结的 Provider ID 与 Model ID，不复用聊天当前模型，也不静默切换供应商。
- 事实采集与模型调用必须在写事务外执行；只允许短事务 CAS 领取与落盘终态。同一用户同时最多一个进行中的模型调用，每天自动调用次数在领取时原子预占，失败或未知结果不释放额度、不自动重试。
- 邮件采用两段式冻结：AI 等待期间 `email_status='WAITING'` 不进入发送队列；成功或到期后一次性写入最终正文并转为 `PENDING`。结果晚到不得补发第二封邮件，也不得改写已冻结副本。
- 撤销授权、清除数据或扩大范围必须禁用未冻结的 AI 副本；清除同时删除本用户的复盘摘要、目标、建议与观察，保留最小授权审计。
- 模型输出必须经确定性校验后保存：只允许本次白名单证据、目标、方法与已有行动 ID，拒绝无依据数字、心理诊断与投资承诺；校验通过不保证推理正确。

## 资料库

- `record/` 独立承载按日期组织的个人资料库，内置随记、每日学习、每周复盘、读书心得和每日手记五种类型；产品界面统一称为“资料”，前端不得用自由字符串绕过类型约束。
- 资料标题可空，但标题与正文不得同时为空；富文本 HTML 用于编辑还原，纯文本列专用于搜索和摘要，标签使用正式关联表表达。
- Slash Command 资料引用选择器只分页读取未归档、未回收资料的轻量元数据，使用稳定资料 ID 传递引用，不得为候选列表加载完整正文或 HTML。
- 首页分类使用持久化 `record_tab`：系统 Tab 与用户自定义 Tab 共用同一模型，每条资料明确关联一个 Tab；“全部”仅是聚合视图，不是可写入分类。
- 每周复盘按 ISO 自然周（周一开始）绑定周年份和周序号；同一自然周允许保存多篇复盘，存在至少一篇即视为该周已复盘。
- 资料删除采用回收站软删除，用户主动清空后才永久删除；编辑、状态修改和恢复必须使用版本号避免静默覆盖。
- “每日手记”必须通过稳定 `source_reference` 在资料与日历之间双向同步：任一入口创建或编辑后另一入口立即可见；删除、回收与恢复动作必须同步维护对应投影，避免重复资料或孤儿数据。
- 资料附件通过通用文件资产模块保存，新文件位于数据库同级的 `files/objects/`；`records/attachments/` 仅用于兼容迁移前的附件。所有读写均须先校验资料所有者，单文件大小必须受限。
- 完整备份使用版本化 ZIP 格式，必须同时包含结构化恢复清单、人类可读 Markdown 和附件原文件；导入前先校验格式，并明确告知用户会替换当前资料库。

## 自动任务

- `automation/` 保存独立的任务配置、执行快照、通知渠道与确认状态；不得复用聊天子 Agent 的 TaskDto 或运行表。
- 所有任务写入必须检查当前用户，修改使用配置版本；调度必须保证同一计划实例唯一，手动执行另记来源。预览仅计算内容和下次时间，不产生真实投递。
- 已删除任务可按版本恢复为暂停状态，恢复不得立即触发调度；用户确认清空后，必须在同一事务中先删除当前用户已删除任务的执行历史，再永久删除对应配置，不能影响未删除任务或其他用户。
- 日报、周报、月报通过日记录、跨域支出投影及学习领域 Service 读取数据；日报统计任务时区内计划执行日当天截至生成时的数据并与前一天比较，周报统计上一个周一至周日并与上上周比较，月报统计上一个自然月并与上上月比较。各栏目本期与上期读取失败独立降级，无记录与不可用分开表达；支出按币种分别汇总，周期待办按实际发生周期去重。报告快照一旦生成，邮件重试只能复用原内容。
- 邮件复用本地已验证账户和 SMTP 配置，发信前再次检查总开关与收件地址；未知提交结果记录为 `UNKNOWN`，不可自动重发。凭据不写入任务表、接口响应或业务日志。
- 久坐时间仅接受桌面原生采样，不读取屏幕与按键内容；达到空闲阈值、锁屏、超出任务生效时段或采样中断时暂停计时并保留已累计值，无法观测的间隙不得补算。后端重启后继续使用数据库中已保存的累计值；待确认提醒按任务去重。系统通知回执和人工确认分别记录。
- 报告邮件当前仅提供蓝调摘要；旧样式标识和旧自定义模板在读取时归一为蓝调摘要，旧自定义字段不参与渲染，未知样式拒绝保存。模板配置随任务保存，执行时冻结渲染后的 HTML 与原报告，重发复用原快照；已生成的历史邮件快照保持原样。
- 邮件排队有效期从本次入队时间计算；显式重试刷新入队时间但保留原执行时间、正文与样式。历史窗口通过任务 SSE 触发按需读取，不定时轮询。
- 无需确认的任务由安装版系统通知展示真实内容，前台须请求横幅与声音；开发模式无稳定包身份时用应用消息与声音呈现。需确认的任务在固定尺寸的全局提醒窗口呈现，久坐提醒先停止声音并完成配置的休息倒计时，倒计时结束才调用后端确认并开始下一轮使用计时；后端待确认状态期间不得重复生成提醒。
- 后端任务 SSE 在事务成功提交后冻结权威快照，建连与重连先返回完整快照；不设两分钟总时长限制，独立心跳不得查库。网络发送在领域锁外按连接串行进行，慢连接只保留最新待发快照，合并时必须保留历史失效信号。
- 纯计时快照使用 `activityOnly` 标记，产生执行记录时不得标记为纯计时。REST/SSE 共用后端实例来源 `sourceId` 和递增读取序号 `revision`；前端拒绝旧序号及已退役来源，重启更换来源，不持久化运行态序号。
- 前端以完整快照判定同步恢复，通知投递和采样失败与连接状态隔离；重连、唤醒恢复及手动重试不得自动重放有副作用的操作。后台调度和邮件发送不依赖前端窗口定时器。

## 长期复盘

- `review/` 的局部契约位于 `src/main/java/butvan/agent/network/review/AGENTS.md`。长期复盘使用当前后端的 SQLite 保存用户级授权、事实摘要与目标，默认关闭；当前只建设基础能力，不能把保存授权视为已启用自动模型调用。
- 后续自动报告复盘仅能使用独立、版本化、可撤销且绑定模型接收方与数据范围的授权；聊天／Slash Command 的财务分析继续逐次确认。长期授权不得被这些命令复用，真实模型调用接入前必须再次审核授权与执行状态机。
- 事实经领域 Service 读取，金额按币种与分值保存；历史账本回溯不等于历史快照。事实、用户确认目标与 AI 推测必须分开；个人上下文仍须接入既有唯一 seam，禁止独立无限注入历史。
- 子级契约索引：`src/main/java/butvan/agent/network/review/AGENTS.md`（授权、模型连接指纹、摘要与目标）；实施规划见根目录 `docs/自动长期记忆复盘教练实施方案.md`。

## 模型配置

- `POST /agent/model/test-connection` 使用 `SetModel` DTO 与 `ModelFactory` 发起有界的实际请求，不写入配置、不切换运行模型；供应商错误只返回稳定中文提示，日志只记录错误类型。
- 模型全量配置写入是显式替换模型列表，允许删除最后一个模型并清理运行实例；其他模块的配置节点继续合并保留。写入前校验自定义地址和协议，具体字段、鉴权与测试要求见根目录 `docs/自定义模型API配置.md`。

## 接口与测试

- Controller 只负责请求转换、当前用户解析与响应包装；领域规则必须位于 Service 或类型处理器。
- Agent 聊天流必须使用稳定 `runId`；`POST /agent/chat/runs/{runId}/cancel` 只做身份、session 与 DTO 适配，实际取消行为必须委托 `server-agents` 的活动运行注册表。该接口应幂等，响应的 `accepted` 只表示服务端已接管，前端只能以 SSE `cancelled` 或详情同步判定终态。
- HITL 使用 `POST /agent/chat/permission/decisions` 原子提交当前批次的全部未决工具决定、`POST /agent/chat/permission/resume` 恢复原运行，并由 `GET /agent/chat/{sessionId}/permission/pending` 返回包含全部未决工具的权威快照；恢复请求的 `runId` 必须与审批创建时一致。旧的单条决定接口仅保留兼容，不得作为桌面端主流程。
- 日历月视图只能读取轻量日期摘要；`GET /agent/daily-events/days` 的 `items` 附带每天最多四条 `{ id, type, title }`，标题最多 80 字符，按日程、待办、学习、手记优先排序，周期待办遵循现有日期规则且不投影到未来；完整手记和类型详情按日加载。悬浮详情按日组合待办、收支、资产流水、学习统计和资料，各来源独立降级。资产变动使用 `GET /agent/finance/transactions/day?date=YYYY-MM-DD`，按当前用户隔离并返回 `TransactionResponse` 列表（无记录返回空列表，缺失或非法日期按参数错误处理）；包含划账和校准，但这两类不得计入收入支出合计。
- 日历周期便签通过 `GET /agent/daily-events/recurring-todos?date=YYYY-MM-DD` 读取所选日期所在自然周与自然月内已生效的每周、每月待办；响应必须包含真实发生日、当前周期完成状态和乐观锁版本，普通与每日待办不得进入该接口。
- SQLite 集成测试必须通过公开 Service 或 HTTP 接口验证行为，不得把私有 SQL 实现作为测试契约。
