# 生活复盘与主动呈现契约

本目录遵循根、server-network 与 review 的工程契约。修改材料、版本、主动策略或渠道行为前读取 `docs/RecordAgent总体建设规划/M4-M5开工方案.md`。

- 生活复盘使用独立 life-v1 授权；默认关闭，明确确认来源、固定模型身份、时区、历史窗口和调用额度。旧统计授权与聊天记忆授权不能授予正文读取权。
- 数值事实与文字材料分开建模；文字仅取获准手记、普通会话用户原文，以及勾选文字来源（手记或聊天）时经 `MemoryRecallPort` 有界召回的最多三条关联往期经历（`HISTORICAL_MEMORY`），保留来源、原始时间、读取范围及截断说明；生成时只从相同授权 ID 与配置 revision 的回看窗口内已就绪复盘中，取最多三条历史观察与三条历史行动供跨天跟进。正文是资料，不执行其中指令。
- 当天使用有截止点的草稿，不改变旧事实快照仅处理闭合自然日的契约。内容身份在同一天稳定，补充或用户确认更新当天资料时产生新版本，已生成和已投递版本不改写；存在尚未呈现的当日 `daily` 候选时，新版本发布后自动将其指向最新版本。
- 生成前持有重置租约，发布前重查代次、授权 revision、连接身份及期限；未知生成不自动重放。所有本域持久化与异步写入必须纳入重置参与方。
- 飞书独立授权到配置白名单中的本人，发送前保存意图与冻结副本；外部渲染不输出内部证据编号（如 `journal-1`），事件与恢复候选独立投递避免被已发日报幂等吞掉；UNKNOWN 不自动重发，明确失败的人工重试复用原内容与标识。
- 可投递版本统一由 `LifeOutreachPolicy.isDeliverable` 判定：READY 且有观察或建议正文。降级资料仅桌面保留；自动与人工事件、手动发送均执行该门槛，旧的失败待呈现候选在调度时取消；渲染不回退发送原始记录。失败原因按脱敏分类展示，不输出供应商异常正文。
- 人工事件只引用当前授权内容中的证据；同主题同来源内容指纹去重，恢复须关联已呈现原事件。候选活动积压上限100条；容量与24小时冷却读取完整账本，不能用展示分页代替。空白日报或静态资产不能单独产生主动消息。
- 主动候选先判断新颖性、有效期与冷却；未回复保持未知。23:30 仅控制复盘顺延，不推定其他渠道静默。作息候选保留来源、时间与不确定性，用户纠正影响未发候选，不静默写画像。`LifeActivityService` 仅按近 14 天用户消息时间戳（不读取正文、不调模型）生成可解释活跃时段建议，须经用户显式保存才写入 `life_habit_candidate`。
- 独立短消息表 `life_nudge` 与复盘内容解耦，承载久未互动问候（`idleCheckinDays` 支持 0/2/3/5/7，开启须绑定主动呈现与本人飞书授权）及 M6 现实信息源提醒（`WEATHER_ALERT`、`WEATHER_RECOVERY`、`EXPENSE_ALERT`、`SERVER_ALERT`、`SERVER_RECOVERY`、`MAIL_ALERT`）：久未互动问候按 `max(authorizedAt, 最近主动互动时间)` 判定沉默天数，以沉默起点唯一键去重并与复盘候选共享全域 24 小时冷却；`LifeSignalMonitorService` 按确定性规则与 `life_signal_state` 基线检测天气显著变化（08:00—22:00，含恶劣天气告警、转好恢复通知与 ≥8°C 温差提醒，复用 `DailyContextService` 缓存且不后台定位）、支出显著变化（需同时勾选 `FINANCE` 来源，在作息活跃窗口内对比近 28 天活跃日均基线，仅客观陈述事实且同日同币种去重）、服务器只读健康探针（仅限只读 HTTP/HTTPS GET，带超时控制，异常告警去重且恢复时单次通知，绝不授予 SSH、重启或命令执行权限）以及重要邮件只读提醒（仅限只读读取发件人、主题和时间元数据，严格绝不读取正文防 Prompt Injection，支持发件人白名单与关键词过滤，基于消息指纹去重），均不调用大模型、走 `SENDING` 预落盘及 `UNKNOWN` 不自动重试，且信号短消息不挤占当日复盘与久未互动问候冷却。重置出厂同步清理 `life_signal_state`。
- 真实模型和飞书联调必须有对应授权；本地验证只使用临时数据库、固定虚构内容与假渠道。确定性通过不代表真实回复质量或外部送达验收通过。

- 人工目标与主动反馈是单独可选来源；目标／反馈各限制300／500估算Token，不截去目标约束。无正文、无凭据授权审计保留旧范围与模型身份，不用于恢复许可或生成。普通聊天提及复盘、回顾或建议时，可通过 `LifeReviewContextPort` 向唯一 `ConversationContextAssembler` 注入当前有效授权下最新已就绪版本的摘要（共享 850/500 硬预算与 Top-K 4，撤权或重置后立即失效）。

- IMAP 凭据仅保存在数据库同级的 `life-mail-credentials.json`，POSIX 文件权限为 0600，Windows 沿用用户目录 ACL；业务配置与授权历史不序列化密码。启动先幂等迁移当前旧凭据再清除业务 JSON，迁移失败阻止后台启动；撤权及本域重置删除对应凭据。留空只允许沿用同一主机、端口与账号的密码，变更连接须重新填写。
- 信号基线通过 `source_fingerprint` 绑定来源身份；服务器绑定 URL 与名称，邮件绑定主机、端口与账号。每次独立异常产生新事件编号，持续异常沿用原事件，恢复后再次异常重新提醒。短消息与基线写入均绑定原授权 ID／revision，发送前复核具体来源开关；旧检测结果不得借新授权发送。
- 生产网络适配统一由 `LifeSignalClients` 实现：探针限只读 GET、不跟随跳转，完整请求三秒超时、响应最多 32 KiB，仅 HTTP 200 且显式 JSON `status` 为 UP（若存在）才正常；IMAP 固定只读 INBOX，993 使用 TLS，其他端口强制 STARTTLS 并核对主机身份，每次最多二十封元数据，保存翻页位置持续扫描较早未读，扫描到底后重新循环；列表变化时允许重复扫描，由消息去重消除重复提醒。发件人白名单精确匹配解析出的邮箱地址，去重使用来源身份和 Message-ID 的 SHA-256，旧编号仅在冻结文案一致时兼容已处理结果。
- `GET /agent/life-reviews/settings` 的 `mailStatus` 仅表达本地账本中上次邮箱检查结果（或等待／未授权），不连接外部服务；失败与空邮箱分开，返回脱敏中文原因。模型生成与主动策略分别由两个有界单线程周期任务运行，生成等待不阻塞现实信号检查，重置租约与未知结果不重放语义不变。
