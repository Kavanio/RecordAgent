# 长期复盘模块契约

本目录遵守根目录与 server-network 的 AGENTS.md。修改授权、事实或目标时先阅读根目录 `docs/自动长期记忆复盘教练实施方案.md`，以实际阶段记录区分已实现与规划。

## 当前阶段

- 仅提供用户级配置、独立授权、结构化历史事实摘要和明确目标；不创建模型调用、不接自动任务执行器、不改变既有邮件。公开响应必须说明 `generationAvailable=false`。
- 默认关闭；配置保存不是授予权限。授权必须显式确认 policyVersion、绑定固定 Provider ID、模型、协议、地址指纹、数据域、周期和最长窗口；扩大范围或改变接收方后必须重新授权，撤销立即使本地摘要写入权限失效。
- 聊天与 Slash Command 不得复用本模块的授权；后续真正的模型请求必须在发送前重新校验授权、连接身份和预算。

## 目录与数据职责

- `controller/` 仅做协议适配，当前用户由 CurrentUserProvider 提供，所有方法标注 ApiLog。DTO 正文不得在日志中展开。
- `dto/` 只保存独立请求／响应契约；`model/` 为内部领域记录；`repository/` 仅访问 review 领域表；`service/` 封装校验、事务与跨领域只读组合。
- 新表使用追加式 Flyway 迁移，业务路径仍为 `~/.butvan-agent/data/butvan.db`；测试只使用临时数据库。
- 模型身份只读检查用户现有 config.json，不自动初始化／改写文件，不测试模型连接，不保存 Key，也不接受客户端提交可信的地址指纹。
- 金额为最小单位整数，分币种；时长为秒；计数为整数。缺失来源独立标为 UNAVAILABLE，不当作零。失败不保存原始异常或用户备注。
- 摘要只处理已结束自然日，最多回看 180 天、单次最多 7 日；不收集当天未闭合窗口，不从邮件文本反向解析，不读取聊天／资料正文。
- 显式清除必须在同一事务中关闭配置、撤销授权、删除当前用户的快照／目标；采集落盘前重新检查配置与授权版本，防止清除后数据复活。过期快照当前在查询时不可见、下一次采集时清理，完整后台保留期清理仍须在模型自动执行上线前补齐。
- 原始账本补录后重新采集产生新指纹，但已冻结的旧摘要不改写；摘要用于历史证据，不宣称是不可变历史账本。
- 用户目标只由用户显式创建、修改和归档；不能把模型观察写成用户目标或画像。所有写入使用 revision／事务，所有查询检查 owner，列表有数量上限。
