# server-feishu 工程规范

本文件是 `agent-backend/server-feishu/` 模块的强制性工作契约，遵循仓库根目录 `AGENTS.md`。

## 职责

- 本模块只负责即时通讯渠道集成（当前为飞书）：长连接事件接收、消息归一化处理、调用 Agent 并回复、渠道配置读取。
- 本模块维护渠道任务受理、FIFO 队列、状态提醒、会话绑定关系及出站投递账本；不替代通用会话和 transcript。
- 主动推送及其他渠道后续能力也归本模块；当前聊天回复只发普通文本，不恢复流式卡片或逐字刷新。
- 不承载 Agent 编排、模型工厂、会话持久化等领域逻辑；这些必须复用 `server-agents` 的既有服务。

## 依赖与分层

- 只允许依赖 `server-agents` 及通用基础设施（Spring、飞书 SDK、Lombok）；禁止被 `server-agents` 反向依赖。
- 包结构：`butvan.agent.feishu.config`（配置读取）、`butvan.agent.feishu.service`（渠道服务）；禁止堆叠无职责说明的 common/utils 目录。
- 网络层通用能力（Controller、AOP、API 日志）仍留在 `server-network`，本模块不得重复实现。

## 配置与安全

- 飞书 App ID / App Secret 只从 `~/.butvan-agent/config.json` 的 `feishu` 节点读取，格式：
  `{ "enabled": true, "appId": "...", "appSecret": "...", "allowedSenderIds": ["本人 open_id"] }`。首版必须明确且仅配置一个本人 open_id，只接收私聊；空白名单和旧配置安全禁用，不推断本人身份，不允许群聊。
- 变更配置、回复交互、状态目录或部署方式前，须阅读本目录 `README.md` 的配置迁移、发送幂等窗口、人工补发及单实例限制。
- 禁止把密钥写入 yml、源码、日志或异常信息；日志中不得出现完整敏感请求体。
- 未配置时保持禁用；连接初始化及退避重试在后台执行，不得阻塞主应用启动。建连超时和退出后须关闭迟到连接，首次成功后的断线重连由 SDK 负责。
- 长连接生命周期由 `FeishuChannelLifecycle` 统一管理，禁止在业务代码中自行建立连接。
- 飞书渠道当前按用户显式决策启用“完全访问”：工具权限请求由渠道自动批准并继续执行，不再走桌面端审批。仅适用于机器人仅限本人使用的场景；如恢复审批，需同步还原 `FeishuAgentRunner` 中的自动批准逻辑。

## 受理、执行与投递契约

- 每条原始消息独立受理；禁用 SDK 短消息合并。先把任务和固定 runId／turnId 落盘，再发普通文本回执；重复 messageId 不重复执行。同一会话有界串行，全局运行并发有上限，控制命令不进入普通等待队列。
- 实际执行默认 60 秒首提醒、之后每 60 秒一次；使用单调时钟，不额外调用模型。提醒是独立普通文本，每次使用新平台 uuid；回执和同一最终分段的重试保持各自稳定 uuid。终态或停止收尾期间丢弃未发提醒，不能承诺撤回已在途请求。
- 最终结果只使用通用运行层已落盘的精确轮次快照，长文本按 JSON 字节数与 Unicode 安全位置无损分段。所有终态及权限恢复均需处理；整轮截止时间不因增量、提醒或审批恢复续期。真正解注册前保留运行槽位。
- 渠道账本仅保存在 `~/.butvan-agent/channels/feishu/<应用与用户命名空间>/state.json`；本地文件锁限制同目录单实例，原子替换并刷盘。账本损坏或写入失败时冻结受理与投递并请求停止任务，不以空账本兜底。主机间共享机器人需要人工保证仅一个后端运行，本实现没有跨主机租约。
- 执行状态与投递状态分离；发送前落盘 SENDING，确认后才记 SENT。只对明确可重试错误有界退避；网络超时、5xx 和发送中重启记 UNKNOWN，不自动重发。回复 API 的 SDK 去重窗口为 1 小时；自动投递保守限制在首次尝试后 50 分钟内，不能承诺永久 exactly-once。
- 重启时精确核对 turnId：已完成的恢复投递，未执行／未完成的标记中断，不自动重放模型或工具。人工补发只处理保存的回复；UNKNOWN 需用户明确接受重复风险后使用 `/resend`。
- 修改原子持久化、调度、提醒或发送行为时，必须补充对应 seam 的失败／竞态测试；使用临时工作区、假发送器和可控时钟。真实飞书发消息属于外部写入，需另行授权。

## 验证与交付

- 新增逻辑至少执行 `mvn compile` 与贴近的单元测试，并说明未验证范围。
- 修改依赖或 SDK 用法后，说明已验证范围和遗留风险。
