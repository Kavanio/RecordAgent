# 飞书渠道配置与故障处理

## 1. 当前能力与限制

- 只接收配置中指定的本人私聊文本与纯图片消息，群聊关闭；图文混排（post）会提示将文字和图片分开发送，不会丢掉正文只识别第一张图；保留本人渠道已有的工具自动批准策略。
- 图片消息要求当前模型在桌面端「模型配置」里标注了图片识别能力；未标注时直接回复中文说明，不下载图片也不调用模型。图片按文件头嗅探格式，仅接受 PNG／JPEG／WebP／GIF 且不超过 10 MiB；下载或校验失败会直接终止该条消息并提示重发，不重试、不落盘，也不会进入聊天记录与 Token 用量。
- 先持久化受理，再立即发送普通文本回执；同一会话有界 FIFO 排队，不合并原始消息。
- 长任务默认执行 60 秒后发第一条“仍在处理”，之后每 60 秒一次；只根据真实状态提醒，不额外调用模型。
- 完成后发送完整回答，不创建流式卡片；回复以卡片 JSON 2.0 的富文本组件渲染 Markdown（标题、列表、引用、行内代码、代码块、表格），回执与状态提醒仍是普通文本。卡片富文本要求飞书客户端 7.20 及以上；低于该版本只会看到升级提示。
- 长文按段落与 Unicode 安全位置拆分，标注序号，不截断正文；若分段切开围栏代码块，上一段自动补闭合围栏、下一段用同一语言标记重开，保证多段都能正常渲染。账本只保存正文原文，卡片在发送时生成，人工补发不会改变内容。
- 回答采用主 Agent 最终结果快照，先保存 transcript、释放运行注册，再交给渠道发送。消息发送失败不会重新执行模型或工具。
- 本实现是单实例可靠性增强，不是多机高可用集群。网络、磁盘、模型供应商或主机故障仍可能中断服务，不保证绝对实时、断电零丢失或永久 exactly-once。

## 2. 配置与旧版本迁移

在**实际运行后端的系统用户**的 `~/.butvan-agent/config.json` 中增加／修改 `feishu`，保留文件其他节点；不要把真实配置提交到仓库，也不要把 App Secret 发给其他人：

```json
{
  "feishu": {
    "enabled": true,
    "appId": "你的飞书应用 App ID",
    "appSecret": "仅填写在本地的 App Secret",
    "allowedSenderIds": ["ou_本人的open_id"],
    "heartbeatSeconds": 60,
    "executionTimeoutSeconds": 600,
    "queueTimeoutSeconds": 600,
    "maxQueuedPerSession": 5,
    "maxConcurrentRuns": 2
  }
}
```

`allowedSenderIds` 必须且只能包含一个本人 `open_id`，不要使用机器人 open_id、union_id 或其他应用的用户 ID。可从同一应用的飞书开发者事件调试信息中确认本人发送者的 `sender_id.open_id`；配置过程不要泄露事件全文或临时访问 Token。

**旧配置缺少白名单时不会连接。** 这是安全迁移，不自动猜测本人身份。配置保存后重启后端生效，不支持运行中热更新。不要同时启动本机和服务器上的同一个机器人；文件锁只能防止同一状态目录内的重复实例。

| 字段 | 默认值 | 允许范围 |
| --- | --- | --- |
| `heartbeatSeconds` | 60 | 30～600 秒 |
| `executionTimeoutSeconds` | 600 | 60～3600 秒，整轮绝对期限 |
| `queueTimeoutSeconds` | 600 | 60～3600 秒，仅等待阶段 |
| `maxQueuedPerSession` | 5 | 1～20 条，不含当前执行项 |
| `maxConcurrentRuns` | 2 | 1～4 个会话，仍受通用运行注册表互斥约束 |

模型须先在桌面端完成配置。初始化失败不会阻塞主应用；连接失败后台退避重试，首次成功后的断线重连交给 SDK。未配置／缺少白名单／参数越界时保持停用，检查后端启动日志。

## 3. 日常交互与命令

普通消息受理后回复“已收到，正在处理…”；存在前序任务则报告前方数量，实际轮到执行时可再提示开始。排队期间不发送执行心跳。

| 命令 | 作用 |
| --- | --- |
| `/stop` | 停止当前任务，保留等待队列；确认取消前显示正在停止，不能立即承诺外部副作用已撤回 |
| `/clear` | 清空尚未执行的消息，不停止正在执行的任务；如要全部停下，可先 `/clear` 再 `/stop` |
| `/new` | 当前没有执行／排队任务时新建对话绑定；旧会话和历史不会因此删除 |
| `/retry <任务ID>` | 重新投递明确失败的回复段，不重新执行任务；不处理 UNKNOWN |
| `/resend <任务ID>` | 用户明确接受可能重复后补发 UNKNOWN／失败段，不重新执行任务 |
| `/ack <任务ID>` | 用户确认此前已实际收到该回复：不重发、不重执行，只解除该会话的投递暂停 |

任务 ID 会在投递失败提示中给出，命令只接受属于当前聊天的任务。只有完整匹配才识别命令，普通语句里提到“停止”不会触发取消。

同会话存在发送状态不确定或失败的回复时，该会话的后续回复会暂停自动发送；此时新消息的回执会直接带上 `/ack` 或 `/retry`、`/resend` 的任务 ID，不会静默停摆。控制反馈（包括 `/ack` 本身）不被这个暂停阻塞，否则用户将无法自救。

执行、发送分别维护状态，区别“任务已完成”和“用户已收到”。停止或超时后会等待 Agent 真正收尾再执行下一条；如果底层工具不响应取消，不提前释放槽位冒险并发运行。已经发出的文件、邮件或外部操作不能保证撤销。

## 4. 投递、容量和重启

渠道私有数据位于：

```text
~/.butvan-agent/channels/feishu/<appId 与本地用户派生的命名空间>/
├── channel.lock       # 本地进程独占锁，正常情况下由进程自动管理
└── state.json         # 绑定、受理去重、任务及回复分段投递状态
```

通用会话、正文及 Token 用量仍按原路径保存，不搬到渠道账本。`state.json` 含待发送回复，是敏感用户数据；POSIX 目录权限为 0700、文件为 0600，Windows 继承运行用户目录 ACL，应限制其他账户访问。

- 全局最多 100 条排队任务、5000 条渠道记录、64 MiB 状态文件；为控制／错误反馈保留 128 条记录空间。已送达终态超过 7 天时，在下一次受理时清理；UNKNOWN、失败和未决投递不会自动删除。
- 达到上限会拒绝新任务，不静默丢弃旧任务。未决记录过多时应先核对投递、人工补发；不要删除账本来“重试”，否则会丢失去重与发送状态。
- 原子替换前先刷入文件，在支持 POSIX 的本地文件系统上同时刷目录元数据。Windows 依赖原子替换和文件系统日志；不支持原子替换的文件系统会拒绝写入。
- 一旦写入失败或账本损坏，停止受理及投递，并请求停止运行任务；不创建空状态继续执行。修复磁盘空间、权限或从可信备份恢复后重启。
- 最终段发送前先记 SENDING，成功确认后记 SENT；限流按退避与 `Retry-After` 处理，最多 4 次尝试，已确认段不重复发送。
- SDK 回复接口的 uuid 去重窗口为 **1 小时**；自动重试保守限制在首次尝试后的 50 分钟内。不同提醒各有新 uuid，同一最终段的自动重试保留稳定 uuid。
- 网络超时、HTTP 5xx、成功响应缺少消息 ID，或重启发现 SENDING，都视作 UNKNOWN。自动发送暂停后续段及同会话后续普通结果（包括该会话自身历史的待定状态），控制反馈始终可发；确认已收到用 `/ack`，确认风险后补发用 `/resend`，不要重新发送原任务来补结果。
- 重启后按固定 turnId 核对 transcript：已完成的只恢复回复投递；未执行／未完成的标记中断并反馈，不自动重放副作用任务。检查实际外部结果后再决定是否重新发起。
- 退出时先停止受理和提醒，再请求取消并保存结果。如果任务／发送尚未确认退出，保留本进程锁直到进程结束，禁止同进程重新打开并行消费者。

提醒在终态后取消，未发的过时回执／提醒会丢弃；网络已经接收的请求无法撤回，不能保证所有在途状态通知都比最终结果先到达。

## 5. 排查顺序与验证

1. 未连接：检查 `enabled`、应用凭据、本人白名单、飞书机器人能力、事件订阅和后端网络；不要在日志中输出密钥。
2. 没反馈：先确认发给当前应用的是本人私聊文本，再看是否处于状态存储冻结／队列满／模型未配置。日志按 taskId、runId 关联，不记录正文。
3. 长时间等待：区分排队、模型／工具执行、正在停止与消息投递；心跳不是进度百分比，也不会延长执行上限。
4. 发送失败：先核对是否已收到。UNKNOWN 必须人工决定是否补发，不能把网络异常当作平台一定未接收。
5. 状态损坏：停止全部该机器人实例后备份数据，再修复权限／容量或从可信备份恢复；禁止手工删除未决段、运行锁或任务记录以强行继续。

日志分别记录受理、排队耗时、终态正文长度及段数、通知种类、平台发送耗时与投递状态，不写正文、工具参数、App Secret 或带临时凭证的 WebSocket URL。

本地验证在 `agent-backend/` 使用 Java 21：

```bash
mvn -pl server-feishu -am compile
mvn -pl server-feishu -am test
mvn -pl server-network -am test
```

自动测试使用临时存储、假发送器、假图片下载器、模型事件重放及可控时钟，不发送真实飞书消息。真实飞书联调需用户单独授权，至少验证两次心跳、长文末尾、连续消息、停止、断网及错误权限，并确认卡片真的渲染出标题、列表与代码块而不是原样 Markdown；图片能力还需验证真实识别结果、超限被拒、未标注视觉能力的模型被拒三种情况，未经联调不能宣称线上投递已验证。
