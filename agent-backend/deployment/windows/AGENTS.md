# Windows 原生后端部署契约

本目录仅保存独立 Windows 后端的启动、更新、停止、日志和配置模板，不承载业务逻辑。修改这些脚本、产物清单或数据迁移步骤时，同时阅读根目录 `AGENTS.md` 与 `agent-backend/WINDOWS.md`。

- 双击 BAT 调用 Windows PowerShell 5.1；BAT 使用 CRLF、UTF-8 无 BOM，PS1 使用 UTF-8 BOM，兼容中文和空格路径。
- 后端以当前普通用户在独立隐藏控制台运行 Java 21；不提升 Agent 权限、不安装系统服务。关闭更新或日志窗口不结束后端；自动开机启动不属于默认行为。
- 更新先下载并校验固定版本产物，再正常关闭本脚本持有的后端、备份整个用户数据目录，最后替换 JAR。PID 必须同时核对创建时间和命令行；禁止按进程名批量停止 Java，禁止强杀后继续替换。
- 停止使用独立辅助进程向目标控制台发送 Ctrl+C，并等待进程退出；失败或超时停止更新。数据库迁移失败时保留现场，不自动回退旧 JAR。
- 默认监听 127.0.0.1:8081，强制 API Token。数据固定为配置的用户主目录下 `.butvan-agent/`，与发布目录分离；真实配置、凭据、日志、备份和 JAR 不入库。
- 已授权仅 `recordagent/backend/*` 匿名 `s3:GetObject`；其余范围保持原权限，不授予匿名列目录或写入。CI 合并具名策略、保留其他语句，冲突时失败保护；上传凭据仅由 GitHub Secrets 注入。
- Windows 仅使用内置 HTTPS 下载，不依赖 MinIO Client 或下载凭据。下载限制实际字节、验证固定提交路径、大小与 SHA-256；禁止把清单中的任意 URL 当作下载指令。旧配置中的 mc 字段忽略并兼容默认下载地址。
- 首次运行仅在缺失时从模板生成配置；既有文件不覆盖。缺少业务 Token、配置格式错误、Java 不可执行和 HTTP 下载失败均提供明确中文提示。
- 多次双击的启动、停止和更新共用文件锁；端口被其他程序或 Docker 占用时失败保护。迁移前先关闭原容器并禁用其自动重启，避免双调度器。
- 测试必须使用临时目录及模拟进程/下载，不启动真实业务后端、不访问个人数据或生产 MinIO。Windows 控制台信号与 BAT 双击需在真实 Windows 另行验收。
