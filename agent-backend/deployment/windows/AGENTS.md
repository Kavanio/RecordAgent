# Windows 原生后端交付契约

本目录根部的四个 BAT 是唯一需要用户复制的交付文件。`source/` 保存可维护的 PowerShell、配置模板、日志配置与测试，不作为额外交付依赖。修改本目录前同时阅读根 `AGENTS.md` 和 `agent-backend/WINDOWS.md`。

- 四个 BAT 由 `agent-backend/scripts/build-windows-launchers.py` 从源码确定性生成并入库。修改源码后重新生成，交付前运行 `--check`，明文分段由生成器统一维护，不在多个 BAT 中分别修改逻辑。
- BAT 使用 CRLF、UTF-8 无 BOM，内置可审查的明文源码；普通 PowerShell 5.1 `-File` 执行生成的 PS1（UTF-8 BOM、CRLF）。每个 BAT 都须独立工作，支持空格、中文和单引号路径；引导命令不得超过 Windows cmd 的单行长度限制。
- 自动生成内容统一在 BAT 同级 `data/` 下；内部源码按明文摘要隔离，四入口共用操作锁。只导入缺失的新配置，不覆盖已有配置，不自动删除旧部署文件。
- 引导仅提取明文文件；脚本执行遵循系统现有策略，源 BAT 的 Zone.Identifier 传递给派生文件。不编码、压缩或动态求值执行脚本，不自动覆盖执行策略或解除来源限制；安全软件拦截须保留证据并交由用户／厂商复核，不承诺自动放行。
- 当前普通用户运行 Java 21，独立隐藏控制台保留正常关闭能力；不提升权限、不安装系统服务。关闭 BAT 或日志窗口不结束后端，开机启动不属于默认行为。
- MinIO 只上传固定的 `backend/butvan-backend.jar`，不再上传 ZIP、JSON 清单、校验文本或脚本。Windows 从同一次 HTTPS GET 的 JAR 正文与对象元数据验证大小、SHA-256、提交号和可执行 JAR 结构后才停机。
- 更新须正常关闭持有的进程，备份整个业务目录后才能替换。PID 同时核对创建时间、启动标记和 JAR 路径；禁止按名称停止其他 Java，禁止强杀后继续替换，数据库迁移失败不自动回退。
- 首次业务 Token 使用隐藏输入并只存本机，配置文件限制为当前用户、SYSTEM 与管理员可读写；下载无需凭据。默认仅监听 127.0.0.1:8081 并强制 Token，业务数据仍在配置用户主目录下 `.butvan-agent/`。
- 已授权仅 `recordagent/backend/*` 匿名 `s3:GetObject`，不增加匿名列目录或写入，保留其他策略；上传凭据仅由 GitHub Secrets 注入。变更下载权限、持久化或进程生命周期后同步维护 DOX。
- 测试使用临时目录与本机模拟下载，不启动真实业务后端、不访问个人数据；真实 Windows 执行策略、来源标记、控制台信号、双击与安全软件判定需要另行验收；非 Windows 的模拟结果不能替代这些结论。
